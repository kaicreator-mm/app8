# V04-MLA external GitHub pre-dispatch freeze witness — P1-A

Stacked on #182. A **live** production HTTPS provider call must execute `verify_github_freeze_witness(ledger)` before `reserve`, which reads GitHub REST plus GraphQL using a private host-scoped token and exact Issue #166 comment ID/author env settings. No user-provided witness JSON or injectable network response exists in the production dispatch signature.

**Exact reviewer-to-campaign binding:** An independent reviewer FIRST checks the prospective 24 job/source contexts, all 12 role-input SHA256 pins, model profiles, two selection seeds, unique nonce, protocol/scorer and numeric budget, then publishes one unedited GitHub comment containing separate exact lines `VERDICT=PASS_FOR_PILOT_PROVISIONAL_ONLY` and `ADMISSION_SUBJECT_SHA256=<64 lowercase hex>`. The digest is computed using `admission_subject_sha256(proposed_manifest)`, which canonicalizes every freeze field **except** the `r2_verdict_comment_id` (the review comment ID is unknowable until after posting). After review the operator fills this returned comment ID into the final manifest, calls host `freeze`, and publishes the independent timestamped witness. Provider preflight rejects any PASS whose subject hash differs or has multiple contradictory subject lines. This closes reviewer-PASS reuse from another campaign without a self-referential commitment loop; it does **not** prove the reviewer actually inspected the private 24 jobs.

The freeze witness comment must be created from `freeze_witness_body(private_manifest, first_freeze_mac)` and contain exact SHA256(canonical manifest), random campaign nonce, first local FREEZE MAC and independently approved R2/R3 verdict comment ID. REST author (host-pinned `APP8_MLA_GITHUB_WITNESS_AUTHOR`), independently different host-pinned reviewer (`APP8_MLA_GITHUB_REVIEWER_AUTHOR`), exact body, timestamps and GraphQL `lastEditedAt=null`/`userContentEdits.totalCount=0` must agree. Rejected/revised independent reviewer verdict, duplicate visible freeze witness for this study, omitted/edited comment or unavailable live GitHub API => **no HTTPS provider dispatch**. The reviewer account must differ from witness author. The independent PASS verdict comment is also verified through GraphQL `lastEditedAt=null` and `userContentEdits.totalCount=0`, preventing a previously posted `NEEDS_REVISION` comment from being retrospectively edited into `PASS`. GitHub token never enters Git or model input; exact comment ID and expected author are host env settings.

**Before first live run:** the reviewer must post a real `VERDICT=PASS_FOR_PILOT_PROVISIONAL_ONLY` after independently reviewing new exact HEAD/metric freeze. Current R2 verdict is NEEDS_REVISION and cannot pass. The user/operator must post the actual freeze comment *after* approved protocol, all 24 real job digests and secret baseline are sealed and *before* any provider response. This PR does not generate a fake public commitment.

Security boundary: these checks prove that an unedited comment is **currently visible** and was published on GitHub before the gated request. They do **not** independently prove provider invocation, rule out deleted past comments, privilege abuse, alternate unguarded HTTP paths, tampering of host-local evidence or establish semantic truth. A single-study witness rule prevents concurrently visible best-of-N freezes but cannot by itself prove nothing was deleted historically; qualified audit should retain off-host mirrored append-only records. True source-only experiment admission is still blocked until approved P1-B/C/D and review. No SE10/SE11 PASS or Release.

No-network tests; actual live GitHub credential/network behavior must be verified on the user's trusted host before any eligible pilot.
