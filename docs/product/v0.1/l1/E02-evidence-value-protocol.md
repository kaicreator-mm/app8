# E02 — Executable Evidence Decision-Value Protocol

Status: PREREGISTRATION_DRAFT  
Gate: L1-EVIDENCE-VALUE  
Supports: PCL-002, PCL-003  
Depends on: E00 PASS

## Product question

When typed invocation and enforcement are held fixed, can executable Provider-behavior evidence improve admission/currentness decisions beyond publisher/static declarations?

## Key isolation rule

Baseline and treatment use:

- the same Provider/invocation case;
- the same typed invocation surface;
- the same enforcement runtime/policy;
- the same generic enforcer configuration;
- the same task/policy requirements.

The measured variable is **Provider-behavior evidence**.

This protocol does not compare "sandbox vs no sandbox".

## Shared decision procedure

Before any arm output is generated, freeze one exact deterministic admission/decision procedure and its digest/rule-set version.

Both S and E MUST use that identical procedure.

The procedure MUST be deterministic for the frozen run. If it contains any model/sampling component, deterministic execution settings and seed are frozen into the decision-engine digest.

- S receives static/publisher declarations + version/build metadata + fixed enforcement baseline + the explicit marker `provider_behavior_evidence = ABSENT_BY_ARM_DESIGN`.
- E receives those exact same inputs plus generated Provider-behavior evidence.

The S-arm absence marker models a declaration-only comparator and MUST NOT be interpreted as a production verified-path "missing required evidence" error. S applies only the frozen declaration-based admission rules. This experimental comparator is not a claim that the product verified path permits evidence-free execution.

Any arm-specific decision logic, rule change, model change, seed change or threshold change invalidates the run.

## Evidence-pipeline inputs

For every case, the treatment evidence pipeline may receive only:

- the exact Provider artifact/build identity;
- the typed invocation/contract under test;
- publisher/static declarations and public specification material also available to S;
- the fixed enforcement configuration;
- case fixtures/specifications authored or selected without access to the Independent Curator's hidden truth label.

The pipeline MUST NOT receive:

- curator truth labels;
- answer-key refutation classes;
- per-case metadata derived from hidden labels.

The pipeline inputs and fixture/source digests are recorded for audit.

## Baseline S — Static declaration

Decision input includes the shared inputs above and no Provider-behavior conformance result.

## Treatment E — Executable evidence

Decision input includes everything in S plus Provider-behavior evidence generated by the E00-approved detector/conformance pipeline during the experiment.

Treatment does not receive hidden ground-truth labels or a pre-populated refutation answer key.

## Hidden evaluation corpus

Freeze before execution:

- **>= 160 materially false-safe/stale cases**;
- **>= 160 valid/safe-declaration cases**;
- >= 50% derived from historical real regressions/version drift/security advisories/real old-vs-new behavior where feasible;
- remaining cases may be independently constructed blind cases;
- labels held by an Independent Curator and unavailable to the evidence-generation pipeline.

Synthetic cases test conditional detection and do not estimate prevalence. Population impact is calculated separately from E01.

## Fixed statistical method

The paired difference criteria use **Newcombe's paired-proportions hybrid-score interval based on Wilson score limits** at 95% confidence.

Wald/normal intervals that collapse to zero width at zero discordance are prohibited.

The exact analysis script implementing this method, all thresholds, the decision-engine digest and corpus sizes are frozen in GitHub **before any experimental arm output is generated**.

## Arithmetic feasibility rule

Before the hidden corpus is frozen, calculate PASS reachability from the exact frozen sample sizes.

The corpus is invalid to freeze unless all primary criteria admit PASS with a non-zero stated error budget.

At the minimum valid-case size n=160, under the fixed Newcombe method:

- benign non-inferiority criterion 4 remains reachable with at least **two E-only false denials when S allows those cases**;
- zero-discordance lower bound is strictly above -0.05.

The feasibility calculation and script output are committed before arm outputs. If the frozen corpus fails this rule, E02 remains NOT_RUN/BLOCKED rather than being executed into a predetermined FAIL.

## Primary outputs

For S and E decisions:

- pre-execution false-safe detection/denial;
- valid-case allow/deny;
- UNKNOWN rate.

For E evidence separately:

- REFUTED;
- NOT_REFUTED;
- UNKNOWN;
- detected refutation class.

## Primary PASS criteria

All must hold:

1. **Evidence-level treatment sensitivity** for hidden false-safe/stale cases:
   - numerator = cases where treatment evidence itself outputs REFUTED;
   - UNKNOWN or evidence-generation failure is **not** a detection;
   - lower Wilson 95% bound >= 0.80.
2. **Evidence-level treatment specificity** for valid cases:
   - numerator = cases where treatment evidence outputs NOT_REFUTED;
   - UNKNOWN or evidence-generation failure is **not** a specificity success;
   - lower Wilson 95% bound >= 0.90.
3. **Decision-level incremental false-safe detection over Static**:
   - using the shared decision procedure;
   - Newcombe paired 95% CI lower bound for `E_correct_deny - S_correct_deny` >= +0.20.
4. **Decision-level benign admissibility non-inferiority**:
   - Newcombe paired 95% CI lower bound for `E_valid_allow - S_valid_allow` >= -0.05.

## FAIL and attribution

FAIL if any primary criterion is not met at the preregistered maximum sample or if protocol integrity is broken.

Attribution is per criterion:

- criterion 1 or 2 failure => `PCL-002 = NOT DEMONSTRATED`, `K2 = TRIGGERED`;
- criterion 3 or 4 failure => `PCL-003 = NOT DEMONSTRATED`, `K3 = TRIGGERED`;
- failures in both groups trigger both K2 and K3.

Any required failure keeps:

~~~text
PRODUCT_FREEZE = NO
~~~

A narrower successor product requires a new PRD.

## Population-impact estimate

After E01 and E02 complete, report an expected-impact model using:

- E01 false-safe prevalence estimate;
- E02 conditional detection improvement;
- E02 false-denial rate.

This model is descriptive evidence. It cannot rescue an E01 or E02 Gate failure.

## No Agent-selection claim

E02 does not claim that an Agent selects the best among multiple Providers.

Provider ranking/selection is not part of PCL-003 or the v0.1 MVP thesis.

## What Was NOT Proven

E02 does not prove:

- arbitrary-input safety;
- production sandbox correctness;
- universal Capability abstraction;
- third-party attestation trust;
- final implementation architecture.
